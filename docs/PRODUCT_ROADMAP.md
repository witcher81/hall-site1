## 9. רשימות תכנון אירוע (Event planner)

**חוויית משתמש**

- המשתמש יוצר **פרויקט אירוע** (למשל: חתונה / בר מצווה).
- לכל פרויקט מוסיפים **פריטים** מסוגים שונים:
  - אולם (קישור ל־`Venue` או טקסט חופשי)
  - צלם, DJ, קייטרינג, … (קישור ל־`Provider` / שירות או טקסט)
- אפשרות: סטטוס לכל פריט (לא נבחר / בהתעניינות / סגור), הערות, תאריך יעד.

**כיוון טכני (הצעה)**

| שכבה | הצעה |
|------|------|
| DB | `EventPlan` (userId, type: WEDDING \| BAR_MITZVAH, title, eventDate?, city?) + `EventPlanItem` (planId, category: VENUE \| PHOTO \| DJ \| CATERING…, linkedVenueId?, linkedServiceId?, status, notes) |
| API | `GET/POST/PATCH /api/event-plans` + פריטים מקוננים או `/items` |
| UI | דף `/my-plans` או תת־אזור ב־SEEKER – רשימת פרויקטים, כרטיס פרויקט עם טבלה/קנבס |

**תלויות** – מודל משתמש מחובר (כבר קיים), עדיף לבנות אחרי ש־favorites / פניות יציבים.

## 10. התראות (In-app + אימייל)

**סוגי אירועים (דוגמאות)**

| טריגר | תוכן למשתמש |
|--------|----------------|
| פנייה נענתה | בעל אולם או ספק ענה על הפנייה |
| בקשה חדשה | (לבעל אולם) פניה חדשה לאולם |
| אולם חדש בעיר שלך | אולם נוסף בערים שמוגדרות בפרופיל / בחיפוש האחרון |

**כיוון טכני (הצעה)**

| שכבה | הצעה |
|------|------|
| DB | `Notification` (userId, type, title, body, readAt, metadata JSON, createdAt) + אינדקס לפי userId + readAt |
| אימייל | אופציונלי: `POST` ל־Resend/SendGrid אחרי יצירת רשומה (או תור job) |
| Realtime | שלב 1: polling או רענון בכניסה; שלב 2: SSE/WebSocket או Pusher |
| UI | פעמון ב־`HomeHeader`, דף `/notifications` עם סימון כנקרא |

**תלויות** – מיפוי אירועים קיימים בקוד (פניות, הודעות) ל־`Notification.create`.

## 11. AI – הצעת אולמות בשפה טבעית

**דוגמה**

> משתמש: "חתונה ל־300 אנשים באזור המרכז"  
> מערכת: מציגה רשימת אולמות ממוינת ומסבירה בקצרה למה.

**כיוון טכני (הצעה)**

1. **Parse intent** – מודל שמחלץ: `minGuests/maxGuests`, `region` (מרכז / עיר), `eventType`, אולי תקציב.
2. **חיפוש מבני** – להריץ את אותו `/api` או Prisma query שכבר קיים (סינון לפי קיבולת, עיר/אזור) – לא מסתמכים על AI ל־SQL ישיר.
3. **הסבר טקסט** – LLM מסכם את התוצאות (או רק מנמק Top 3).

**אבטחה ועלות**

- Rate limit per user/IP
- אין להעביר PII ללא הסכמה
- מפתח API בצד שרת בלבד

**תלויות** – חיפוש אולמות חזק (מיקום, אזורים), אולי שדות `region` / `lat/lng` במסד.

1. **התראות (פנימיות)** – ערך מיידי, מתחבר למסלולים הקיימים.

3. **AI** – אחרי שחיפוש + מסננים יציבים, כדי שהתוצאות יהיו אמינות.
